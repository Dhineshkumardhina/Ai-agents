## Detailed Evaluation by Architecture Dimension

### 1. Execution Sandboxing & Security Isolation
Execution isolation is the single most critical architectural requirement when autonomous agents write and execute code.

- **OpenHands (Grade: A):** Provides enterprise-ready container isolation. Every agent session is bound to an isolated Docker container (`openhands-workspace/openhands/workspace/docker/docker_workspace.py`) or Kubernetes sandbox pod (`k8s-agent-sandbox`). Workspaces are mounted securely, and host environments are completely isolated.
- **OpenAI Codex (Grade: A+):** Achieves the lowest runtime overhead by replacing heavy containers with kernel-level sandboxing: Bubblewrap (`bwrap`) and Linux Landlock LSM (`landlock.rs`) on Linux, native Windows Sandbox on Windows, and Seatbelt sandbox profiles on macOS. Modifies files only in an explicitly whitelisted directory.
- **SWE-agent (Grade: A):** Uses `swerex` (`swerex/deployment/docker.py`) to launch disposable Docker containers with non-root privileges.
- **Open SWE (Grade: B-):** Relies on cloud-hosted remote microVMs (LangSmith / Daytona). Self-hosted local Docker setups require significant reverse-engineering of LangSmith contracts.
- **Paperclip (Grade: B):** Focuses on the control plane. Sandboxing is offloaded to runner plugins or external tools. Server chat channels (Slack, Discord) and external connectors are cleanly housed in `server/src/services/chat-channels/` and `server/src/services/connectors/`.
- **Cline (Grade: C):** Runs in the developer's local shell process. It uses confirmation dialogs to prevent unauthorized operations, but headless automated runs pose host compromise risks without an external container.
- **MetaGPT (Grade: F):** Directly executes arbitrary generated Python code on the host operating system without containerization or permission gates.

### 2. Multi-Agent Organization & Task Management
- **Paperclip (Workforce Orchestration Champion):** The only repository that models a full autonomous software company. Features an organizational chart, manager-subordinate reporting hierarchies, project boards, task delegation, budget spending limits, and human-in-the-loop approval workflows. Standardizes subagent execution via native Agent Client Protocol (ACP) support (`packages/adapter-utils/src/acpx-engine` with `@agentclientprotocol/claude-agent-acp: 0.73.0` and `@agentclientprotocol/codex-acp: 1.6.2`).
- **MetaGPT (Planning & SOP Champion):** Excels at structured requirement engineering. Translates ideas into Product Requirement Documents (PRDs), system architectures, and task dependency trees through specialized persona agents (`ProductManager`, `Architect`, `ProjectManager`). Note: `setup.py` restricts runtime to `python_requires=">=3.9, <3.12"`.
- **OpenHands (Runtime Task Champion):** Manages tactical code modification tasks via `task_tracker` and `planning_file_editor`, supporting sub-agent delegation (`openhands-tools/openhands/tools/delegate`).
- **Open SWE (Review Workflow Champion):** Encapsulates software engineering workflows into LangGraph state machines, with production execution migrated to Managed Deep Agents (`mda/agent.py` using `managed_deepagents`), while `openswe.graphs.agent:traced_agent` remains a 6-line read-only stub.
- **Cline (Autonomous Task Engine):** Implements an SQLite-persisted autonomous workflow engine with live file watching (`agenda-task-manager.ts`).

### 3. Model Provider Abstraction
- **OpenHands & SWE-agent:** Utilize `litellm` to provide universal model connectivity (OpenAI, Anthropic Claude 3.7 Sonnet, Google Gemini 2.0 Flash, Ollama, DeepSeek R1/V3, AWS Bedrock).
- **Cline:** Implements a clean native TypeScript abstraction (`@cline/llms`) supporting all major models without Python bridges.
- **OpenAI Codex:** In addition to OpenAI API endpoints (`gpt-4o`, `o1`, `o3-mini`, `codex-mini`), Codex provides first-class native support for local open-source models via Ollama (`codex-rs/ollama/`) and LM Studio (`codex-rs/lmstudio/`) activated via the `--oss` flag (`DEFAULT_OSS_MODEL = "gpt-oss:20b"` / `"openai/gpt-oss-20b"`). Direct third-party cloud routing (e.g. Anthropic Claude via LiteLLM) is not natively implemented.
- **MetaGPT:** Supports multiple providers via custom client classes, but lacks modern dynamic routing, cost tracking, and fallback failovers.
